FHIR namespace

Every canonical URI carried by a CARLON Equine Biometrics bundle is defined on this page: what the term means, and where the specification defines it normatively.

https://vitalkultur.com/carlon-equine/fhir/
Specification 0.3 (Draft) · page updated 2026-08-14 · licence CC BY 4.0

These URIs are identifiers. FHIR requires an Observation.code.coding.system, an identifier.system or a meta.profile entry to be a URI; it does not require the URI to be fetched, and no conformance rule in the specification depends on fetching anything. A URI carrying the https:// scheme nevertheless promises resolution — so these resolve, here.

If you are holding a bundle with https://carlon.equine/…

That is a pre-0.3-final bundle, and it is not invalid. The namespace base moved on 2026-08-14, because .equine is not a delegated top-level domain and those URIs could therefore never resolve. Map the old base onto the new one segment for segment — nothing else changed: no code, no structure, no meaning. Consumers MAY accept both bases; producers conforming to 0.3 MUST emit only the new one. Rationale: §4.1.

1. Identifier systems

The namespaces a Patient.identifier may be qualified with, so that a recording can be matched onto a horse in a third-party system. A producer SHOULD emit every identifier it holds; a consumer MUST match on any of them. Normative: §5.1.

https://vitalkultur.com/carlon-equine/fhir/subject

The subject identifier assigned by CARLON Equine — stable for the life of the horse's record within this system, and meaningless outside it. It is the fallback anchor when no external identity is available.

Also defined by usMeaningSection
urn:carlon:clinic-patient-idThe patient number held by the clinic or practice management system that produced or received the recording.§5.1
urn:carlon:equine-passportThe identifier printed in the horse's equine passport.§5.1

These two are urn: identifiers by design: a URN makes no promise of resolution, which is the honest form for a namespace that has no page behind it. Bundles additionally carry the external systems https://www.ueln.net (UELN), urn:iso:std:iso:11784 (microchip) and https://data.fei.org (FEI ID), none of which are ours to define.

2. Structure definitions

What a bundle declares itself to be. Normative: §4.

https://vitalkultur.com/carlon-equine/fhir/StructureDefinition/equine-biometrics-bundle

The bundle profile. Bundle.meta.profile MUST include it. The profile requires one Patient (the horse), one Device carrying sensor and analysis provenance, and at least one Observation, each with a UCUM unit and a category. Normative: §4.

https://vitalkultur.com/carlon-equine/fhir/StructureDefinition/animal-species

The extension on Patient that states the species. FHIR R5 has no species element on Patient, and a biometrics bundle that does not say which animal it describes is not interpretable. Normative: §4.

4. The beat-label vocabulary

The labels carried inside the rr-beat-labels attachment, as run-length pairs ([["N",26],["LS",1],…]) positionally aligned with the raw series. The vocabulary is closed: a third vocabulary is not permitted, and a label carries the same meaning in every output of the same producer. Normative: §5.4.1.

LabelMeaning
NNormal beat.
LSLong–short pair.
SPremature beat.
AVBRR pattern of the second-degree AV-block type — a physiological, vagally mediated pattern and the most frequent rhythm finding in the resting horse.
LLong RR consistent with a missed R wave — an equipment observation, not a cardiac one.
XDiscarded: a beat that enters no derived value. Never a statement about what the beat was.

L and AVB both describe a long interval and MUST NOT be merged. A producer that cannot separate the two MUST label the beat X rather than guess — emitting L asserts that the distinction was actually made.

5. Conformance levels

What an implementation claims it can do. An implementation SHOULD state its level; a conformance claim without a stated level is meaningless. Normative: §2.1.

https://vitalkultur.com/carlon-equine/fhir/CodeSystem/conformance-level
CodeNameRequirement
L1ConsumerReads a conformant bundle and ignores unknown codes without error (§7).
L2ProducerEmits a conformant bundle: Patient + Device + ≥1 Observation, UCUM units, declared provenance.
L3Verifiable ProducerL2 plus the raw RR series (§5.4), so that every derived value can be independently recomputed.

A producer that holds a classification it cannot align positionally with the raw series MUST declare the lower level it actually reached rather than the level it aimed at.

6. Specification version

https://vitalkultur.com/carlon-equine/fhir/spec-version

Carried as a Bundle.meta.tag, its code being the specification version the bundle was built against — e.g. 0.3. A bundle that states its level and its version can be judged; one that does not has to be guessed at. Normative: §4.

The criterion that matters

Conformance at L3 is executable, not a prose promise: export → import → re-derive, with the raw RR series bit-identical and every derived value reproducible to the published rounding precision of its code (§2.2). A format that cannot survive its own round trip is a file format, not a standard.

Not a diagnostic specification. This vocabulary defines how measurements travel, never what they mean. It carries no reference ranges, no thresholds, no classification and no risk scores; interpretation belongs to the attending veterinarian and is deliberately outside its scope.
