How it works for the facility

1 · Get the fileFrom the operator panel, the controller web server or a USB stick, after the session.
2 · Add it to the recordUnder the rehab session tap “Import controller log” and choose the file. Check the mapping the first time.
3 · DoneVisite remembers the profile per device. After that one tap is enough; manual entry remains as a fallback.

For manufacturers: the open format

Visite reads many file formats itself. For a new export, this format is best: one row per second, semicolon, decimal point, UTF-8.

schema_version;machine_id;session_id;timestamp;elapsed_s;speed_kmh;incline_pct;water_depth_cm;water_temp_c
1.0;aquatrainer-1;session-001;2026-11-23T09:05:00Z;300;4.5;0.0;40.0;18.0
  • timestamp with time zone (Z or +01:00); alternatively the controller date and time or seconds from start.
  • speed_kmh belt speed in km/h, incline_pct incline in percent (not degrees), water_depth_cm water depth above the belt surface, water_temp_c in °C.
  • Missing value: empty field, never 0. No names of horses, owners or customers in the file.
  • Visite also recognises other column names, comma as decimal separator, m/s, mph or °F.

Live, every second

If your controller or a gateway outputs the values continuously, for example a Siemens S7 through its web server or a LOGO! 8.4 through MQTT, Visite takes them during the session and creates the stages itself once new values hold for 30 seconds. Set it up in the recording under “Live values from the controller”: choose the route, enter the address, “Connect and test”. Incoming values appear with a suggested meaning; one tap saves it for the device.

Network addressVisite polls an address on the facility network every second, e.g. http://192.168.0.10/werte.json. The response needs the headers Access-Control-Allow-Origin: https://vitalkultur.com and Access-Control-Allow-Private-Network: true. Chrome and Edge ask once whether Visite may access the local network.
MQTTThe controller publishes to a broker on site (LOGO! 8.4 supports general MQTT brokers). Visite reads via encrypted WebSocket, e.g. wss://broker.facility.local:8884, with a certificate; the browser does not allow unencrypted ws:// from the web version. Enter the topic the LOGO! publishes to. Run the broker with user accounts inside the protected machine network.
BluetoothOnly Chrome or Edge on Android and desktop; Safari, iPhone and iPad do not support Bluetooth in the browser. A gateway with the open CARLON profile 1.0: service c4a7a000-5e2d-4f1c-9b6a-0e1e9a5c0001, value with notification c4a7a001-…0001, content as text.
{"speed_kmh": 4.8, "incline_pct": 2.0, "water_depth_cm": 40, "water_temp_c": 18.5}
speed_kmh=4.8;incline_pct=2.0;water_depth_cm=40;water_temp_c=18.5
  • Both notations work, including nested JSON and your own names; you check the mapping during setup.
  • Visite only calls read methods: polling over the network, a subscription for MQTT, notifications for Bluetooth. This is enforced technically by the rights in the controller (read-only user) and a separate machine network.
  • The strap keeps recording the heartbeats. If the live connection drops, the recording stays complete and the stages can be added from the file.
Making it work togetherIf connecting your controller does not work right away, or you have another idea such as a different route or additional values, we work out the solution with you. An example file or a short capture of the live values is enough to start.

Siemens LOGO!, S7 and other controllers

  • LOGO! 8: a data log function block writes CSV with timestamps to the microSD card; record values every second (Siemens states at least 500 ms). From LOGO! 8.4 the data log can be downloaded through the built-in web server.
  • S7-1200: DataLogCreate and DataLogWrite create a CSV; download it through the controller web server.
  • S7-1200 from firmware V4.5 and S7-1500 live: Visite reads through the controller Web API (JSON-RPC, HTTPS only; login with a user that may only read variables, then the variables, e.g. "Treadmill".Speed). The controller certificate must be accepted once in the browser or replaced with your own. Where facility IT does not allow this, use the read gateway.
  • LOGO! 8.4 live: the LOGO! publishes to an MQTT broker on site; Visite reads the LOGO! format (state.reported) directly. If the controller sends integers, e.g. 48 for 4.8 km/h, set the factor 0.1 during setup.
  • LOGO! 8.1 to 8.3 and other controllers with Modbus TCP, live: a browser cannot read Modbus itself. The CARLON read gateway (one file, Python 3, no extra packages) runs on a computer on the facility network, reads the configured registers only with the read functions 03 and 04 (open source, about 140 lines) and provides them at http://<computer>:8090/werte.json. In Visite choose “Network address”. Which values are in which registers is defined by the equipment manufacturer. Program comments are in German.
  • Other manufacturers: controllers that output MQTT or JSON over HTTP are set up via MQTT or the network address; Visite suggests the mapping of the values and you check it once. Controllers with Modbus TCP use the read gateway.
  • Visite only reads. It controls nothing and does not interfere with the emergency stop or safety chain. Changes to the controller program are the responsibility of the equipment manufacturer.

For facility IT and manufacturers

TopicHow it is
BrowserMeasuring, Bluetooth and live values: Chrome or Edge on desktop or Android. Safari, iPhone and iPad: view records and reports, no measuring.
Data pathValues go from the controller, the broker or the read gateway directly into the browser on site. They do not go to any Vitalkultur server.
NetworkController in a separate machine network. The measuring device only needs access to the one service you allow: S7 web server (HTTPS, 443), broker (WSS, port of your choice) or read gateway (HTTP, 8090). Only the gateway speaks Modbus (502).
RightsS7: dedicated user with read rights for variables only. LOGO! 8.4: publishes to the broker itself, Visite only subscribes. Read gateway: only Modbus read functions 03 and 04, answers only the configured origin (default: vitalkultur.com).
SecurityRun the broker with user accounts and a certificate. Enabling the web server, MQTT or Modbus on the machine belongs in the manufacturer’s risk assessment; only the manufacturer changes the controller program.
OutageIf the connection fails, the strap keeps recording; stages can be added from the file or tapped. The read gateway reports an unreachable controller and returns the last state with a timestamp.
StagesA stage begins when the values hold for 30 seconds and ends with the first change. Transitions such as filling, draining or braking are therefore not counted in the stage evaluation.
